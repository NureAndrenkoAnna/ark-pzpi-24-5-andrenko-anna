3 ОПИС ВИКОНАНОЇ РОБОТИ
     3.1 Поняття рефакторингу та вибір методів
     
     
     Рефакторинг – це зміна внутрішньої структури програмного коду, яка покращує його зрозумілість і підтримуваність без зміни зовнішньої поведінки програми [1, 2]. Р. Мартін у книзі «Clean Code» наголошує, що чистий код має бути легким для читання та зміни, а підтримка такого стану потребує постійного вдосконалення структури [3, 4]. Тому рефакторинг доцільно виконувати малими кроками й перевіряти, що результат роботи програми не змінився.
     Для роботи з переліку методів, наданого викладачем, обрано три методи, що не мають закріплених за іншими студентами прізвищ. Критерієм вибору було не формальне виконання завдання, а наявність у власному коді реальної проблеми, яку метод вирішує. Відповідність методів фрагментам коду наведено в таблиці 3.1.

     3.2 Метод 1: Convert Procedural Design to Objects
     
     
     3.2.1 Опис проблеми
     У вихідному коді результат вимірювання множення матриць зберігається в структурі MatrixTiming, усі поля якої відкриті. Уся поведінка винесена у вільні функції saveMatrixResult() та displayMatrixResult(): дані й операції над ними розділені (слайд 4). Вираз співвідношення часу r.rawSec > 0 ? r.objectsSec / r.rawSec : 0.0 повторюється в обох функціях, а displayMatrixResult() крім виведення ще зберігає файл і перевіряє збіг результатів. Зміна правила обчислення співвідношення потребує правок у кількох місцях, а будь-яка частина програми може змінити поля структури напряму.
Лістинг 3.1 – MatrixTiming і процедури до рефакторингу (слайд 4)
 1  struct MatrixTiming {
 2      std::size_t n;
 3      std::string type;
 4      double rawSec;
 5      double objectsSec;
 6      int repetitions;
 7      bool equal;
 8      long double sum;
 9  };
10  void saveMatrixResult(const MatrixTiming& r) {
11      // ... відкриття CSV, заголовок ...
12      const std::uint64_t n3 =
13          static_cast<std::uint64_t>(r.n) * r.n * r.n;
14      out << buildMode() << ',' << r.type << ','
15          << r.n << ',' << n3 << ',' << r.rawSec << ','
16          << (r.rawSec > 0
17              ? r.objectsSec / r.rawSec : 0.0)
18          << ... << '\n';
19  }
20  void displayMatrixResult(const MatrixTiming& r) {
21      std::cout << ... << "Object/raw ratio: "
22          << (r.rawSec > 0
23              ? r.objectsSec / r.rawSec : 0.0)
24          << ... << '\n';
25      saveMatrixResult(r);
26      if (!r.equal)
27          throw std::runtime_error("...");
28  }
     
     
     
     3.2.2 Застосування методу
     Метод Convert Procedural Design to Objects перетворює записи даних на об’єкти, а процедури, що працюють із цими даними, – на методи цих об’єктів [1]. Для MatrixTiming це означає: структуру замінено класом із приватними полями; функції збереження та виведення стали методами save() і display(); дубльований вираз винесено в метод ratio(); обчислення n³ – у nCubed() (слайд 5).
Лістинг 3.2 – Клас MatrixTiming (слайд 5)
 1  class MatrixTiming {
 2  public:
 3      MatrixTiming(std::size_t n, std::string type,
 4                   double rawSec, double objectsSec,
 5                   int repetitions, bool equal,
 6                   long double sum);
 7      bool equal() const;     // та інші getter-и
 8      double ratio() const {
 9          return rawSec_ > 0 ? objectsSec_ / rawSec_ : 0.0;
10      }
11      std::uint64_t nCubed() const;
12      void save() const;      // було saveMatrixResult(r)
13      void display() const;   // було displayMatrixResult(r)
14  private:
15      std::size_t n_;     std::string type_;
16      double rawSec_;     double objectsSec_;
17      int repetitions_;   bool equal_;
18      long double sum_;
19  };
     
Лістинг 3.3 – Реалізація display() і save() (слайд 6)
 1  void MatrixTiming::display() const {
 2      std::cout << ... << "Object/raw ratio: "
 3                << ratio() << ... << '\n';
 4      save();
 5      if (!equal_)
 6          throw std::runtime_error("...");
 7  }
 8  void MatrixTiming::save() const {
 9      // ... відкриття CSV, заголовок ...
10      out << buildMode() << ',' << type_ << ','
11          << n_ << ',' << nCubed() << ',' << rawSec_
12          << ',' << ratio() << ... << '\n';
13  }
     
     Клієнтський код змінюється мінімально: виклик функції замінюється викликом методу, а доступ до полів – викликом методів доступу.
Лістинг 3.4 – Клієнтський код до рефакторингу (слайд 6)
1  displayMatrixResult(r);
2  if (!r.equal) throw ...;
3  std::cout << r.rawSec << ...;
     
Лістинг 3.5 – Клієнтський код після рефакторингу (слайд 6)
1  r.display();
2  if (!r.equal()) throw ...;
3  std::cout << r.rawSec() << ...;
     
     3.2.3 Переваги
     Дані та операції над ними зібрано в одному класі, поля інкапсульовано. Вираз співвідношення існує в одному місці, тому правило обчислення змінюється одним виправленням. 
     Порядок дій display() збережено: виведення, збереження в CSV, перевірка збігу результатів із викиданням виняткової ситуації.
     
     
     3.3 Метод 2: Replace Type Code with Subclasses
     
     
     3.3.1 Опис проблеми
     Таблиця таймерів у задачі task2 складається зі значень TimerResult. Рядок name виконує роль коду типу: від нього залежить, як мінімальний крок таймера перераховується в наносекунди (слайд 7). 
     Для time та omp_get_wtime значення множиться на 10⁹, для clock ділиться на CLOCKS_PER_SEC, для двох функцій FileTime множиться на 100, для GetTickCount – на 10⁶, для QueryPerformanceCounter враховується частота, а для chrono значення береться без змін. 
     Назви таймерів дублюються в таблиці та в ланцюжку умов, а новий таймер вимагає нової гілки if.
Лістинг 3.6 – Ланцюжок умов за назвою таймера (слайд 7)
 1  long double ns = -1;
 2  if (e.minStep >= 0) {
 3      const std::string name = e.name;
 4      if (name == "time" || name == "omp_get_wtime")
 5          ns = e.minStep * 1.0e9L;
 6      else if (name == "clock")
 7          ns = e.minStep * 1.0e9L / CLOCKS_PER_SEC;
 8      else if (name == "GetSystemTimeAsFileTime" ||
 9               name == "GetSystemTimePreciseAsFileTime")
10          ns = e.minStep * 100.0L;
11      else if (name == "GetTickCount")
12          ns = e.minStep * 1.0e6L;
13      else if (name == "QueryPerformanceCounter")
14          ns = e.minStep * 1.0e9L / freq;
15      else if (name == "chrono::high_resolution_clock")
16          ns = e.minStep;
17  }
     
Лістинг 3.7 – Запис TimerResult до рефакторингу (слайд 7)
1  struct TimerResult {
2      const char* name;
3      const char* header;
4      const char* unit;
5      long double minStep;
6      long double inNanoseconds;
7  };
     
     3.3.2 Застосування методу
     Тип таймера не змінюється протягом життя об’єкта, а поведінка залежить від нього. 
     У такому випадку Фаулер рекомендує замінити код типу підкласами [1, 5]. Для кожного значення коду створено підклас базового класу TimerResult: SecondsTimer, ClockTimer, FileTimeTimer, TickCountTimer, QpcTimer, ChronoTimer і TscTimer (слайд 8). 
     Базовий клас зберігає дані та має віртуальний метод convert(); метод inNanoseconds() приховує перевірку minStep >= 0.
Лістинг 3.8 – Базовий клас і підклас SecondsTimer (слайд 8)
 1  class TimerResult {
 2  public:
 3      TimerResult(const char* name, const char* header,
 4                  const char* unit, long double minStep);
 5      virtual ~TimerResult() = default;
 6      // name(), header(), unit(), minStep() - getter-и
 7      long double inNanoseconds() const {
 8          return minStep_ >= 0 ? convert(minStep_) : -1;
 9      }
10  protected:
11      virtual long double convert(long double step) const = 0;
12  private:
13      const char* name_;  const char* header_;
14      const char* unit_;  long double minStep_;
15  };
16  
17  class SecondsTimer : public TimerResult {
18      using TimerResult::TimerResult;
19      long double convert(long double s) const override
20          { return s * 1.0e9L; }
21  };
     
     Підклас QpcTimer додатково зберігає частоту лічильника, тому має власний конструктор. Решта підкласів успадковує конструктор базового класу. Для __rdtsc у вихідному коді гілки не було, і значення лишалося рівним −1; щоб зберегти виведення «n/a», підклас TscTimer повертає −1.
Лістинг 3.9 – QpcTimer та інші підкласи (слайд 9)
 1  class QpcTimer : public TimerResult {
 2  public:
 3      QpcTimer(/* як TimerResult */, long double freq);
 4  protected:
 5      long double convert(long double s) const override
 6          { return s * 1.0e9L / freq_; }
 7  private:
 8      long double freq_;
 9  };
10  // ClockTimer, FileTimeTimer, TickCountTimer,
11  // ChronoTimer - як SecondsTimer; TscTimer -> -1
     
Лістинг 3.10 – Таблиця таймерів і цикл виведення після рефакторингу (слайд 9)

     3.3.3 Переваги та ціна
     Умов за назвою немає; новий таймер додається новим підкласом без змін у циклі виведення, а формула кожного таймера лежить поруч із його даними. Ціною є збільшення обсягу коду: з’явилися базовий клас, сім підкласів і покажчики shared_ptr замість значень у векторі. Якби тип таймера мінявся під час роботи програми, доцільніше було б застосувати Replace Type Code with State/Strategy; тут цього не потрібно.
     
     
     3.4 Метод 3: Replace Record with Data Class
     
     
     3.4.1 Опис проблеми
     У задачі task8 результати вимірювань зчитуються з CSV-файлів у std::map. Запис SavedRow має відкриті поля raw, objects та checksum, а розбір рядка виконується прямо в лямбді load(): чотири рядкові змінні, std::getline, stoull і stod (слайд 10). Розмір n існує окремо як ключ map і не входить до запису. Рядок CSV є записом без поведінки, а знання про формат рядка розкидане за місцем використання.
Лістинг 3.11 – SavedRow і розбір рядка у лямбді до рефакторингу (слайд 10)
 1  struct SavedRow {
 2      double raw = 0;
 3      double objects = 0;
 4      std::string checksum;
 5  };
 6  // task8_releaseInstructions(), лямбда load():
 7  std::string nStr, rawStr, objStr, checksumStr;
 8  if (!std::getline(in, nStr, ',') ||
 9      !std::getline(in, rawStr, ',') ||
10      !std::getline(in, objStr, ',') ||
11      !std::getline(in, checksumStr))
12      throw std::runtime_error("Invalid CSV row");
13  std::size_t n = std::stoull(nStr);
14  rows[n] = { std::stod(rawStr),
15              std::stod(objStr), checksumStr };
     
     3.4.2 Застосування методу
     Метод Replace Record with Data Class замінює запис класом даних із приватними полями та методами доступу [1]. Створено клас SavedRow зі статичним методом fromCsv(), у який перенесено розбір рядка (слайд 11). Конструктор за замовчуванням залишено, щоб зберегти запис rows[...] = ... у std::map. Розмір n тепер входить до запису.
Лістинг 3.12 – Клас SavedRow (слайд 11)
 1  class SavedRow {
 2  public:
 3      SavedRow() = default;
 4      SavedRow(std::size_t n, double raw,
 5               double objects, std::string checksum);
 6      static SavedRow fromCsv(const std::string& line);
 7  
 8      std::size_t n() const { return n_; }
 9      double raw() const { return raw_; }
10      // objects(), checksum() - аналогічно
11  private:
12      std::size_t n_ = 0;
13      double raw_ = 0, objects_ = 0;
14      std::string checksum_;
15  };
     
Лістинг 3.13 – Метод fromCsv() (слайд 11)
1  SavedRow SavedRow::fromCsv(const std::string& line) {
2      std::istringstream in(line);
3      std::string nStr, rawStr, objStr, checksumStr;
4      // ... getline x4, інакше
5      //     runtime_error("Invalid CSV row")
6      return SavedRow(std::stoull(nStr), std::stod(rawStr),
7                      std::stod(objStr), checksumStr);
8  }
     
Лістинг 3.14 – Клієнтський код до рефакторингу (слайд 12)
1  std::size_t n = std::stoull(nStr);
2  rows[n] = { std::stod(rawStr),
3              std::stod(objStr), checksumStr };
4  if (d.checksum != r.checksum) { ... }
5  print("Raw", d.raw, r.raw);
6  print("Objects", d.objects, r.objects);
     
Лістинг 3.15 – Клієнтський код після рефакторингу (слайд 12)
1  SavedRow row = SavedRow::fromCsv(line);
2  rows[row.n()] = row;
3  
4  if (d.checksum() != r.checksum()) { ... }
5  print("Raw", d.raw(), r.raw());
6  print("Objects", d.objects(), r.objects());
     
     3.4.3 Переваги
     Поля інкапсульовано, клієнт працює з інтерфейсом класу. Розбір і перевірка рядка зосереджені в одному методі fromCsv(). Поведінку збережено: дублікати n перезаписуються, порожні рядки пропускаються, неповний рядок викликає runtime_error («Invalid CSV row»). Метод не прискорює обчислення, а лише покращує структуру даних.

21          };

 5          : n_(n), raw_(raw), objects_(objects), checksum_(std::move(checksum)) {}
 6  
 7      static SavedRow fromCsv(const std::string& line) {
 8          std::istringstream in(line);
 9          std::string nStr, rawStr, objStr, checksumStr;
10          if (!std::getline(in, nStr, ',') ||
11              !std::getline(in, rawStr, ',') ||
12              !std::getline(in, objStr, ',') ||
13              !std::getline(in, checksumStr))
14              throw std::runtime_error("Invalid CSV row");
15          return SavedRow(std::stoull(nStr), std::stod(rawStr),
16                          std::stod(objStr), checksumStr);
17      }
18  
19      std::size_t n() const { return n_; }
20      double raw() const { return raw_; }
21      double objects() const { return objects_; }
22      const std::string& checksum() const { return checksum_; }
23  
24  private:
25      std::size_t n_ = 0;
26      double raw_ = 0;
27      double objects_ = 0;
28      std::string checksum_;
29  };
30  bool loadFile(const std::string& filename, std::map<std::size_t, SavedRow>&
        rows) {
31      auto load = [](const std::string& filename, std::map<std::size_t,
            SavedRow>& rows) {
32              std::ifstream file(filename);
33              if (!file) return false;
34              std::string line;
35              std::getline(file, line); // Skip CSV header
36              while (std::getline(file, line)) {
37                  if (line.empty()) continue;
38                  SavedRow row = SavedRow::fromCsv(line);
39                  rows[row.n()] = row;
40              }
41              return !rows.empty();
42          };
43      return load(filename, rows);
44  }
